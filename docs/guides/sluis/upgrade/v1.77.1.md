# Upgrade to v1.77.1

v1.77.1 removes storage layout v4 and the tools that moved an installation off it ([ADR 0072](../../../decisions/0072-storage-layout-v5-module-first.md)). History is in the [CHANGELOG](../../../../CHANGELOG.md).

## Before you start

The installation must run layout v5 on v1.77.0 or earlier. v1.77.1 neither reads layout v4 nor migrates from it.

| Check | Expected |
|---|---|
| `secrets` with `source: ssm` | `layout: v5` |
| `ports.dynamodb` or `adapters.state.settings` | `tables`, one per module; no `table` |
| DynamoDB | the module tables only; the v4 table is retired |
| SSM | nothing under `<root>/internal/credentials/`; no layout v4 name of a moved secret (below) |
| the Pulumi program | `Layout: LayoutV5` and no `Compat` other than `RetireLegacyTable` |

An installation still on layout v4 moves with v1.77.0: [v1.75](v1.75.md), [v1.76](v1.76.md), then `sluis migrate v5 prune`.

The layout v4 names of the secrets layout v5 moved are read by nothing on v1.77.1:

| Layout v4 name below `<root>/` | Layout v5 name |
|---|---|
| `internal/credentials/...` | `internal/<module>/...` |
| `internal/config/issuer/state-secret` | `internal/oidc/state-secret` |
| `internal/config/recovery/password` | `internal/oidc/recovery-password` |
| `internal/config/providers/google/<p>/client-id`, `client-secret` | `internal/oidc/signin/<p>/...` |
| `internal/config/clients/<id>/secret` | `internal/oidc/clients/<id>` |

Delete them with `sluis migrate v5 prune` of v1.77.0, or by name. Other names under `internal/config/` stay: the `ssm` source still reads there a name it does not know, such as `valkey/password` or a workspace's `keySecret`.

```sh
aws ssm describe-parameters --query 'Parameters[].Name' --output text \
  --parameter-filters "Key=Name,Option=BeginsWith,Values=/sluis/<instance>/internal/credentials/"
```

## What was removed

| Removed | Use instead |
|---|---|
| `secrets.layout: v4`, and an `ssm` section without `layout` | `layout: v5` |
| `ports.dynamodb.table`, `adapters.state.settings.table`, the installation's `aws.table` | `tables`, one per module |
| `sluis migrate v5` | v1.77.0 |
| `sluis migrate --skip directory` | `--skip google` |
| `sluis serve` | `sluis issuer` |
| Pulumi `Layout`, `LayoutV4`, `LayoutV5`, `LayoutV4V5` on `LambdaArgs`, `RoleArgs`, `KeyPolicyArgs` | nothing |
| Pulumi `CompatArgs`; `Compat` on `LambdaArgs` and `StatesArgs` | nothing |
| Pulumi `StatesArgs.Legacy`, `LegacyStateArgs`, `States.Legacy`, `States.LegacyBackupArn`, `LegacyBackupArnOutput`, `LegacyBackupRetentionDays` | nothing |
| Pulumi `NewState`, `StateArgs`, `State`, `StateType`, `StateGrant.TableArn`, `PortsArgs.TableName` | `NewStates`, `States.Grant()` |
| Pulumi `LambdaArgs.MigrationRoleArn` | nothing |
| Pulumi `StateSecretParameterName`, `RecoveryPasswordParameterName`, `ConfigParameterPrefix` | the `...V5` names |

A document that names a removed key does not load.

## 1. Update the Pulumi program

```diff
 args := &sluispulumi.LambdaArgs{
-	Layout: sluispulumi.LayoutV5,
 }
 roles := sluispulumi.RoleArgs{
-	Layout: sluispulumi.LayoutV5,
 }
-state := &sluispulumi.StateGrant{Tables: tables, TableArn: legacy}
+state := &sluispulumi.StateGrant{Tables: tables}
```

Delete any constant built from `ConfigParameterPrefix` or `StateSecretParameterName`. A layout v5 installation's preview then shows no change.

## 2. Update documents and command lines

| Where | Change |
|---|---|
| `secrets: {source: ssm}` | add `layout: v5` |
| a single table | name the module tables in `tables` |
| `sluis serve` | `sluis issuer` |
| `--skip directory` | `--skip google` |

## 3. Kubernetes with another secrets store

With the `openbao` or `memory` Secrets adapter, the credentials sluis writes move to the layout v5 address. Copy each to its new path, keeping the `<ref>`, before the new version starts. A credential not copied reads as absent, and its connection must be made again.

| Credential | Before | v1.77.1 |
|---|---|---|
| Google Workspace key | `credentials/directory/google/<id>/<ref>` | `credentials/google/workspace/<id>/<ref>` |
| organisation | `credentials/github-org/<org>/<ref>` | `credentials/github/org/<org>/<ref>` |
| link App | `credentials/github-app/link/<ref>` | `credentials/github/app/link/<ref>` |
| catalogue App | `credentials/github-app/<id>/<ref>` | `credentials/github/app/<id>/<ref>` |
| runner App | `credentials/github-runner-app/<tier>/<org>/<ref>` | `credentials/github/app/runner-<tier>-<org>/<ref>` |
| GitHub link | `credentials/github-link/<account>/<ref>` | `credentials/github/link/<account>/<ref>` |
| Slack workspace | `credentials/slack-workspace/<team>/<ref>` | `credentials/slack/workspace/<team>/<ref>` |
| Slack App | `credentials/slack-app/<id>/<ref>` | `credentials/slack/app/<id>/<ref>` |
| console session key | `credentials/console/session-key` | `credentials/oidc/console/session-key` |
| generated client | `credentials/oidc-client/<id>/secret` | unchanged |

## 4. Roll

Roll the service, the modules and the library together. On layout v5 the documents of the two releases are the same, so order does not matter.

## Roll back

Roll back to v1.77.0 with the same documents. With another secrets store, copy the credentials back first.
