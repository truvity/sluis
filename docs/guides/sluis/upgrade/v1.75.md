# Upgrade to v1.75

v1.75 removes secrets layout v3 and `transition`, and `sluis migrate secrets-layout`. Run `secrets.layout: v4` first; an installation still on v3 or `transition` moves on v1.74.x ([steps](../migrate/migrate-secrets-layout.md)).

## The Pulumi library

The first v1.75 apply adopts the v4 copies `sluis migrate` wrote and removes the `private/config` ones. The values are unchanged.

- The state secret and the recovery password are SSM parameters at `/sluis/<instance>/internal/config/issuer/state-secret` and `.../recovery/password`.
- The new parameters have `overwrite` set, so they adopt the copies that already exist, with the value from the same `RandomBytes` and `RandomPassword`.
- The old `private/config/...` parameters are removed from the program and deleted at the end of the apply, after the function is updated.
- The roles lose their grants on `private/*`.

Read the preview first: two parameters created, two deleted, no replacement.

## Move to layout v5

Layout v5 splits storage by module ([layout](../../../reference/sluis/storage-layout.md)). Writes freeze for 10 to 15 minutes.

Before you start:

- Run v1.75 with the Pulumi library on `Layout: "v4"`.
- Declare `controllers.github.appRefs` (organisation to App id) for every GitHub organisation.
- Give no catalogue App the id `link` or one starting `runner-`.
- Keep the KMS key, alias and instance name the same on both sides.

1. Add the v5 tables and apply.

   ```go
   Layout: "v4+v5",
   ```

   Expect 2 parameters created, none deleted or replaced, the `NewStates` tables with the old one adopted as `LegacyState`, and role policy updates ([layouts](../../../reference/sluis/pulumi-library.md#layouts)).

2. Plan. Nothing may be refused.

   ```sh
   sluis migrate v5 plan --from v4.yaml --to v5.yaml
   ```

3. Copy while the writers run. `--skip issuer` needs no flag. Dry run first.

   ```sh
   sluis migrate v5 copy --skip issuer --dry-run --from v4.yaml --to v5.yaml
   sluis migrate v5 copy --skip issuer --from v4.yaml --to v5.yaml
   ```

4. Freeze. Stop the issuer, the console and both controllers, or set maintenance.

5. Copy the changes and the issuer, then verify.

   ```sh
   sluis migrate v5 copy --overwrite --i-have-stopped-writers --from v4.yaml --to v5.yaml
   sluis migrate v5 verify --from v4.yaml --to v5.yaml
   ```

6. Set the layout and apply. The document then carries `secrets.layout: v5` and `ports.dynamodb.tables`.

   ```go
   Layout: "v5",
   ```

7. Sign in, compare the `kid` set with the one before, and check.

   ```sh
   curl -s https://login.example/keys | jq -r '.keys[].kid'
   sluis check --config v5.yaml
   ```

## Roll back

- Never start the v1.75 issuer on v5 before the copy. If it started, copy with `--overwrite`; since #549 the fingerprint follows the source.
- Within 7 days, a return to v4 loses refresh rotations made on the destination. People stay signed in.
- Clear the source's maintenance flag before the v4 restart.

## After 7 days

Set `Compat.DropV4` with `Layout: "v5"` and apply. The 2 v4 parameters are deleted. The legacy table retires later.
