# Upgrade to v1.75

v1.75 removes secrets layout v3, `transition` and `sluis migrate secrets-layout`. Run `secrets.layout: v4` first; an installation on v3 or `transition` moves on v1.74.x ([steps](../migrate/migrate-secrets-layout.md)).

## The Pulumi library

The first v1.75 apply adopts the v4 copies `sluis migrate` wrote and removes the `private/config` ones. Values stay.

- The state secret and the recovery password are SSM parameters at `/sluis/<instance>/internal/config/issuer/state-secret` and `.../recovery/password`.
- The old `private/config/...` parameters are deleted at the end of the apply, after the function is updated.
- The roles lose their grants on `private/*`.

Read the preview first: two parameters created, two deleted, no replacement.

## Move to layout v5

Layout v5 splits storage by module ([layout](../../../reference/sluis/storage-layout.md)). Writes freeze 10 to 15 minutes.

Before you start:

- Run v1.75 with the Pulumi library on `Layout: "v4"`.
- `controllers.github.appRefs` is optional.
- Give no catalogue App the id `link` or `runner-...`.
- Keep the KMS key, alias and instance name.

1. Add the v5 tables and apply.

   ```go
   Layout: "v4+v5",
   ```

   Expect 2 parameters created, none deleted or replaced, and role updates ([layouts](../../../reference/sluis/pulumi-library.md#layouts)).

   An older library wrote the two v5 parameters as plain values, which the plan refuses: apply this release first.

2. Plan. Nothing may be refused.

   ```sh
   sluis migrate v5 plan --from v4.yaml --to v5.yaml
   ```

3. Copy live, dry run first.

   ```sh
   sluis migrate v5 copy --skip issuer --dry-run --from v4.yaml --to v5.yaml
   sluis migrate v5 copy --skip issuer --from v4.yaml --to v5.yaml
   ```

4. Freeze the source; keep the issuer up and Lambda concurrency as is ([how](../../../concepts/sluis/migration-freeze.md)).

   ```sh
   sluis maintenance on --reason "layout v5" --config v4.yaml
   ```

5. Copy the changes and the issuer, then verify.

   ```sh
   sluis migrate v5 copy --overwrite --from v4.yaml --to v5.yaml
   sluis migrate v5 verify --from v4.yaml --to v5.yaml
   ```

6. Rename a blob credential: `internal/blobs/<name>` is `internal/google/blobs-<name>` on v5. Set `CredentialsRef` to that: every process reads it there; copied ones stay. Then set the layout and apply.

   ```go
   Layout: "v5",
   ```

7. Sign in, compare the `kid` set, and check.

   ```sh
   curl -s https://login.example/keys | jq -r '.keys[].kid'
   sluis check --config v5.yaml
   sluis maintenance off --config v4.yaml
   ```

## Roll back

- Never start the v1.75 issuer on v5 before the copy; if it started, copy with `--overwrite`.
- Within 7 days, a return to v4 loses v5's refresh rotations. People stay signed in.
- Run `sluis maintenance off` before restarting v4.

## After 7 days

1. Prune the v4 parameters. The dry run lists what goes and what stays, with a plan hash. It refuses unless every v4 item is `same` on v5.

   ```sh
   sluis migrate v5 prune --dry-run --from v4.yaml --to v5.yaml
   sluis migrate v5 prune --confirm-plan <hash> --from v4.yaml --to v5.yaml
   ```

2. Set `Compat.DropV4` with `Layout: "v5"` and apply. The 2 Pulumi-owned v4 parameters are deleted.

3. Check that `aws ssm get-parameters-by-path --recursive` on the v4 prefixes lists only the kept parameters.
