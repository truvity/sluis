This is the target state, not a running system. Every actor puts its records on the transport and moves on. One writer turns them into ordered batches in a blob (object storage with a lock mode) and has each batch head signed through the keys port, an optional witness cosigns the heads, and an indexer feeds a search index from the same ordered batch stream. There is no notary. The page is drawn from `site/src/data/explorer/audit.yaml`, which today is written by hand from the design; once the permission manifest exists, the actors, sockets and call edges are generated from it. The ideas behind the page are on [Audit](/concepts/audit/); the actors are described under [Actors](/concepts/actors/). The audit actors are the writer, the witness, the indexer and the reader.

Audit shares the sluis port definitions: keys, state, lease, blob, transport, index and cloud, plus witness, the only port audit adds. The same actors, the same records and the same integrity chain run in every installation. Only the drivers behind the transport, keys, state, blob and index ports change. Audit is four separate pieces, the emitter, the log, Search and Quota, and pieces combined in one installation share driver instances, even with sluis ([OD-37](/open-decisions/#od-37)). Pick an installation: local, boards or lambda. The map, the flows, the sockets and the outage table follow it. Without script the page shows boards and every table is plain HTML. A cluster keeps one log per node, and the rule is exactly one writer per log.

## Map and flows

Select a box to see what it holds, what it never holds and who it calls. Choose a flow to step through it: each step lights the lines it uses, in order. Every actor listens on Unix sockets. `entry`'s public API is a Unix socket that the edge connector forwards to on bare-metal, and a loopback port inside the sandbox on serverless, where the Lambda Web Adapter connects to it. The only network listeners are that loopback port and, on a bare-metal cluster, the Raft ports of the rqlite clusters. The architecture explorer shows [the sockets and processes](/architecture/explorer/) of each installation.

Search (the indexer, the search index and the reader) and Quota are separate pieces. Where each runs is derived from the port and driver rules, not decided per installation: see [Ports and drivers](/concepts/drivers/#where-an-actor-runs-is-derived) and [OD-32](/open-decisions/#od-32). Quota meters by default and enforces per policy rule ([OD-33](/open-decisions/#od-33), [OD-38](/open-decisions/#od-38)). The witness is optional everywhere ([OD-36](/open-decisions/#od-36)), and there is no notary ([OD-39](/open-decisions/#od-39)).

## The transport port

The emitter (a library in every actor) and the writer are decoupled by the transport port. It replaces the older queue port and "outbox". The port has two modes. In **direct** mode the producer streams the record to the writer. In **queue** mode the record goes through a spool, SQS or NATS JetStream. In direct mode, when the writer is down, the emitter falls back to a local spool, so direct mode needs a disk and is not available on serverless. A request returns once its audit record is durable on the transport, never waiting for the archive or the index. One contract; the driver behind it depends on the installation. The transport may deliver out of order, twice or late: the sequence is made later, when the writer registers a batch, and the writer dedupes by record id. A writer on the same node as sluis is one installation's placement, not the model.

<AuditExplorer part="transport" />

The installation defaults are a local spool on the bare-metal installations and an SQS queue on serverless and Kubernetes ([OD-22](/open-decisions/#od-22), [OD-34](/open-decisions/#od-34)); direct and NATS JetStream are supported with no default. Kubernetes is proposed and is not drawn here: see [Kubernetes](/runtimes/kubernetes/). The recovery path is separate: it spools locally in every installation and never blocks.

## The integrity chain

How an auditor can tell that nothing was removed, changed or added. The writer has each batch head signed with the log key through the keys port (there is no notary), the heads form a hash chain, a witness may cosign them, and verification never trusts the search index or the state.

<AuditExplorer part="chain" />

The state store sits on the write path of every batch. This is acceptable given the transport, a reconciler that compares the bucket listing with `audit_batches`, and verification that reads the blob and the seals only.

## Search index and lag

<AuditExplorer part="lag" />

The default index of each tested installation is decided in [ADR 0022](/decisions/0022-search-is-an-index-fed-from-the-log-and-the-index-is-one-driver-with-provisioning-modes/): `sqlite` on local, a replicated `rqlite` index on boards, so the reader can run on any node, `postgres` on Aurora on lambda, reached through RDS Proxy ([OD-12](/open-decisions/#od-12), revised), and `postgres` on `cnpg` on Kubernetes. The indexer follows each log's signed checkpoints, so the index lags the log by the seal interval, a few seconds, plus its own pass. Where Search runs is derived from the port and driver rules ([OD-32](/open-decisions/#od-32)): with a `sqlite` index on a cluster, for example, the reader runs on the indexer's node. The search index is a rebuildable cache; the chain in the blob is the record.
