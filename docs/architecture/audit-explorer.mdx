This is the target state, not a running system. Every actor puts its records on the transport and moves on. The writer seals them into a C2SP tiled log in a blob and asks `key-holder` to sign each checkpoint with the log key; an optional witness cosigns the checkpoints, and an indexer feeds a search index from the signed log. The page is drawn from `site/src/data/explorer/audit.yaml`, written by hand from the design. The ideas are on [Audit](/concepts/audit/); the reasoning is in [ADR 0015](/decisions/0015-audit-pieces-transport-search-and-front/), [ADR 0016](/decisions/0016-the-audit-log/) and [ADR 0017](/decisions/0017-audit-records-the-usage-stream-and-quota/).

Audit uses the sluis ports plus `witness`, the only port it adds. The same actors, records and integrity chain run in every installation; only the drivers behind the ports change. Audit is four pieces, the emitter, the log, Search and Quota, and pieces combined in one installation, even with sluis, share driver instances ([ADR 0015](/decisions/0015-audit-pieces-transport-search-and-front/#four-pieces)). Pick an installation: local, boards or lambda. The map, the flows and the outage table follow it. Without script the page shows boards, and every table is plain HTML. The explorer does not draw the Kubernetes installation yet; there the audit side is a separate audit installation ([ADR 0018](/decisions/0018-runtimes-installations-and-delivery-order/#kubernetes)).

## The transport port

The emitter, a library in every actor, and the writer are joined by the transport port. In **direct** mode the emitter streams the record to the writer; in **queue** mode the record goes through a spool, SQS or NATS JetStream. When the writer is down in direct mode, the emitter falls back to a local spool, so direct mode needs a disk and is not available on serverless. A request returns once its audit record is durable on the transport, never waiting for the log or the index. The transport may deliver out of order, twice or late, and the writer removes duplicates by record id.

<AuditExplorer part="transport" />

The installation defaults are a local spool on bare-metal, an SQS queue on serverless and NATS JetStream on Kubernetes; direct is supported with no default ([ADR 0015](/decisions/0015-audit-pieces-transport-search-and-front/#transport)). The recovery path is separate: it spools locally in every installation and never blocks.

## The integrity chain

How an auditor can tell that nothing was removed, changed or added. The writer has each checkpoint signed with the log key through the keys port, each checkpoint commits to the whole log, a witness may cosign it, and verification never trusts the search index or the state.

<AuditExplorer part="chain" />

## Search index and lag

<AuditExplorer part="lag" />

The default index of each tested installation is in [ADR 0015](/decisions/0015-audit-pieces-transport-search-and-front/#search-and-the-index): `sqlite` on local, a replicated `rqlite` index on boards, `postgres` on Aurora on lambda, reached through RDS Proxy, and `postgres` on `cnpg` on Kubernetes. The indexer follows each log's signed checkpoints, so the index lags the log by the seal interval, a few seconds, plus its own pass. With a `sqlite` index on a cluster the reader runs on the indexer's node. The search index is a rebuildable cache; the log in the blob is the record.
