This is the target state, not a running system. The map below is drawn from `site/src/data/explorer/architecture.yaml`, which today is written by hand from the design. Once the [permission manifest](/architecture/) exists, the actors, drivers, call edges, users and sockets are generated from it and this page reads that instead. The vocabulary is explained under [Actors](/concepts/actors/) and [Ports and drivers](/concepts/drivers/). Each preset is an installation of one [environment](/environments/) (bare-metal, serverless or kubernetes), and the presets are listed on [Presets](/environments/presets/). Preset T6 (Kubernetes) is proposed and is not drawn here.

Pick a preset. The map, the tables and the flows follow it. Without script the page shows T4, the first build target, and every table below is plain HTML.

## Processes and listeners

The same facts as tables, for the preset picked above. `entry`'s public API listens on TCP, bound to `127.0.0.1`, in every environment: `cloudflared` connects to that loopback port on bare-metal, and the Lambda Web Adapter does on serverless. Every other actor and driver listens on Unix sockets under `/run/sluis/` only. How Kubernetes reaches the loopback port is on [Listeners](/architecture/listeners/).

Quota and Search are separate boxes whose placement is open: see [OD-38](/open-decisions/#od-38), [OD-33](/open-decisions/#od-33) and [OD-32](/open-decisions/#od-32).

## Clusters

<Proposed>
On bare-metal with N nodes (the presets T2 and T4) each node runs the full set of processes. In the current draft each node's audit writer drains its own spool, and the notary co-signs batch heads 2 of 3 across the nodes, with no separate notary YubiKey. The audit writer declares exactly one instance, so an installation that shares one spool needs the lease port; placement of the audit writer is per installation.
</Proposed>

<ArchExplorer part="cluster" />

Raft peer traffic uses the state driver's own TCP port, over mTLS. It is the only TCP port between nodes.
