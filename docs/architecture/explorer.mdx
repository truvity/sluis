This is the target state, not a running system. The map below is drawn from `site/src/data/explorer/architecture.yaml`, which today is written by hand from the design. Once the [permission manifest](/architecture/) exists, the actors, drivers, call edges, users and sockets are generated from it and this page reads that instead. The vocabulary is explained under [Actors](/concepts/actors/) and [Ports and drivers](/concepts/drivers/). Each tested installation is an installation of one [runtime](/runtimes/) (bare-metal, serverless or kubernetes), and the four are listed on [Installations](/runtimes/installations/): local, boards, lambda and kubernetes. The map draws local, boards and lambda, in the order they are delivered; kubernetes is proposed and is not drawn here.

Pick an installation. The map, the tables and the flows follow it. Without script the page shows boards, one of the three installations built after local, and every table below is plain HTML.

## Processes and listeners

The same facts as tables, for the installation picked above. On bare-metal `entry`'s public API is a Unix socket and `entry` has no network: `cloudflared` forwards to the socket as a `unix:` origin. On serverless it is a TCP port bound to `127.0.0.1` inside the function's sandbox, and the Lambda Web Adapter connects to it. Every other actor and driver listens on Unix sockets under `/run/sluis/` only. On Kubernetes a key-less edge relay container forwards to `entry`'s socket ([ADR 0018](/decisions/0018-runtimes-installations-and-delivery-order/#kubernetes)); see [Listeners](/architecture/listeners/).

Quota and Search are separate pieces whose placement is derived from the port and driver rules, not decided per installation: see [Ports and drivers](/concepts/drivers/#where-an-actor-runs-is-derived), [OD-38](/open-decisions/#od-38), [OD-33](/open-decisions/#od-33) and [OD-32](/open-decisions/#od-32).

## Clusters

On bare-metal with N nodes (the boards installation) each node runs the full set of processes. A cluster keeps one log per node: each node's writer drains its own spool and signs with its own log key, and the other nodes are its peer witnesses (the 2-of-3 co-signing). The rule is exactly one writer per log, not one per installation. There is no notary.
