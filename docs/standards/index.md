This is the register of the standards sluis builds on. Each row says which standard, what sluis uses it for, and where it stands. For the plan to prove conformance, see [Conformance](/standards/conformance/).

## How to read the status

| Status | Meaning |
|---|---|
| **Implemented in v1** | The v1 documentation or code shows it. The v1 reference is linked from the notes where useful ([endpoints](/v1/reference/sluis/endpoints/), [what is not served](/v1/concepts/sluis/not-served/)). |
| **Target in v2** | v2 does it; part of parity, or agreed in the design. |
| **Planned** | Intended, not yet scheduled in detail. |
| **Not planned** | Deliberately not served. v1's list of what is not served is the starting point, and a row can change by a decision. |
| **Parked** | Deliberately deferred, with a dated trigger for taking it up again. |
| **Reference only** | A document that informs a choice. sluis makes no claim of conformance to it. |
| **To verify** | The claim is not yet established from the documentation or code, and a person has to check it before it is relied on. |

A row can carry two statuses, for example "implemented in v1; target in v2". A row on this page is either tied to a feature or to a stated use, or it says plainly that it is not planned, parked or reference only. Issue numbers link to [github.com/truvity/sluis/issues](https://github.com/truvity/sluis/issues).

## Workload identity

Agreed 2026-10-30: machine identity follows SPIFFE. sluis is its own SPIFFE issuer; SPIRE is not deployed, and is read as prior art. A trust domain is a boundary, so each environment has its own trust domain, bundle and issuer. The isolation controls that rest on these rows are in the [threat model](/security/threat-model/).

| Identifier | Title | What sluis uses it for | Status | Notes |
|---|---|---|---|---|
| [SPIFFE ID](https://github.com/spiffe/spiffe/blob/main/standards/SPIFFE-ID.md) | The SPIFFE Identity and Verifiable Identity Document | The name of every machine identity: hosts, Kubernetes service accounts, actors and CI jobs. | Target in v2 | A full claim. Paths are `spiffe://<td>/host/<name>`, `/k8s/<cluster>/ns/<ns>/sa/<sa>`, `/sluis/<actor>` and `/ci/github/<org>/<repo>`; the trust domain is the boundary. An actor has one ID, and its instance (node or unit) is a separate attribute: a DNS SAN or a JWT claim. |
| [SPIFFE Trust Domain and Bundle](https://github.com/spiffe/spiffe/blob/main/standards/SPIFFE_Trust_Domain_and_Bundle.md) | The SPIFFE Trust Domain and Bundle | The per-environment trust bundle that hosts and workloads install. | Target in v2 | A full claim. The bundle is checked against the pinned roots and the signed root list, and a bundle with a lower `spiffe_sequence` is refused. Hosts get it from `sluis trust sync`; Kubernetes from a trust-manager Bundle or a ClusterTrustBundle. |
| [X.509-SVID](https://github.com/spiffe/spiffe/blob/main/standards/X509-SVID.md) | The X.509 SPIFFE Verifiable Identity Document | Host and workload certificates from the `ca` actor, and mutual TLS between actors of different boundaries. | Target in v2 ([#913](https://github.com/truvity/sluis/issues/913)) | A full claim. The SPIFFE ID in a certificate is taken from the requester's authenticated identity, never from the request. |
| [JWT-SVID](https://github.com/spiffe/spiffe/blob/main/standards/JWT-SVID.md) | The JWT SPIFFE Verifiable Identity Document | Workload tokens from the per-environment issuer, which also issues the tokens of actors on nodes, with one key per node card. | Target in v2 | A full claim. `iss` is the boundary's issuer URL and `sub` the SPIFFE ID; between actors of different boundaries the only `aud` is the target's SPIFFE ID. |
| [SPIFFE Federation](https://github.com/spiffe/spiffe/blob/main/standards/SPIFFE_Federation.md) | SPIFFE Federation | Exchanging bundles with the trust domains of other operators. | Planned (later) | Until then trust between installations is declared in the install files. |
| [SPIFFE Workload Endpoint](https://github.com/spiffe/spiffe/blob/main/standards/SPIFFE_Workload_Endpoint.md) | The SPIFFE Workload Endpoint | A local endpoint that hands SVIDs to workloads. | Planned (later) | Today a workload gets its SVID by token exchange. |
| [SPIFFE Workload API](https://github.com/spiffe/spiffe/blob/main/standards/SPIFFE_Workload_API.md) | The SPIFFE Workload API | The API behind the Workload Endpoint, for standard SPIFFE client libraries. | Planned (later) | Comes with the Workload Endpoint. |

| Identifier | Title | What sluis uses it for | Status | Notes |
