A kind is a type of item that the [store](/decisions/0005-the-store/) keeps. The registry lists every kind with its [storage class](/decisions/0004-the-data-model/#storage-classes), scope, [treatment](/decisions/0004-the-data-model/#treatment), [profile](/decisions/0004-the-data-model/#profiles), its one writer and its readers. It is [`docs/architecture/kinds.yaml`](https://github.com/truvity/sluis/blob/main/docs/architecture/kinds.yaml), and everything below is generated from it by `just kinds-write`. `just check-kinds-page` fails while the page is stale, and `just check-registries` keeps the registry true.

The registry is one of the two that generate the rules: see [Rules](/reference/rules/) for the actor, kind and verb matrix and the call graph, and [Keys](/reference/keys/) for the keys that seal a kind. The concepts are on [Data](/concepts/data/). The anchor of a kind is its name in lower case: `/reference/kinds/#datakeywrap`.

### `AuditLog`

The logs of the boundary (audit, usage, issuance): log ids, the verifier key of each log, lock mode, lifecycle tiers, the compliance profile and the per-log retention. The verifier key (`verifier_key`) is the public half of the log's key as a C2SP verifier key text, signed with the rest of the document, so the indexer and the reader take it from the signed config through the data port and from no file. Loaded and verified by store@ like every config kind; the audit pieces read it through the data port.

- **Class:** config; scope boundary; plain; profile Fixed; module core; serves the audit family.
- **Writer:** `IaC`.
- **Readers:** [`writer`](/reference/actors/#writer), [`witness`](/reference/actors/#witness), [`indexer`](/reference/actors/#indexer), [`reader`](/reference/actors/#reader).
- **Exportable:** no; **backed up:** no.
- **Links:** [`AuditWitnesses`](#auditwitnesses), [`AuditCatalogue`](#auditcatalogue).

### `AuditCatalogue`

The catalogue: the action table of the newest release with the JSON Schema of each action's records, as the one item `default`, so the table and its schemas never move apart. Within a major version the table only grows (REQ-AUDIT-119), so it holds for the records of every older release; the writer refuses a record of a newer one. Made by tools/gen/audit and signed by the release pipeline. Loaded by store@ like AuditLog, which refuses an action without its schema, a schema without its action and a schema that does not compile.

- **Class:** config; scope boundary; plain; profile Fixed; module core; serves the audit family.
- **Writer:** `pipeline`.
- **Readers:** [`writer`](/reference/actors/#writer), [`indexer`](/reference/actors/#indexer), [`reader`](/reference/actors/#reader).
- **Exportable:** no; **backed up:** no.
- **Links:** [`AuditLog`](#auditlog).

### `DataKeyWrap`

Id &lt;purpose>/&lt;generation>/&lt;recipient>. Each tenant has five data keys, one per purpose: `data` (personal and operational data), `pseudonym` (keyed hashes, rolled by epoch), `pairwise` (pairwise subjects, never rotated), `evidence` (audit and usage) and `chain` (the facts of a session chain, which session seals and opens and exchange opens). Boundary purposes (tenant `-`): `grant`, `cookie`, `mac` (the key behind key@'s Mac operation) and `data` (the kinds that are sealed and have no tenant: EnrolmentToken, PendingEnrolment). They are generated software data keys, not KMS keys: on AWS key@ calls GenerateDataKey under the boundary's one symmetric KMS key with the encryption context {boundary, tenant, purpose} and stores only the wrapped copy; on boards key@ generates them in software and wraps them by ECDH for each board's card and the recovery recipient. A tenant declared to keep its keys in a customer account has its wraps made under KMS keys of that account (ADR 0006). The value is already ciphertext, so the treatment is plain. A tenant's exit deletes its `data`, `pseudonym`, `pairwise` and `chain` wraps at once (crypto-shred); the `evidence` wrap is deleted when the evidence retention ends, because evidence never shares a key with personal data and outlives it.

- **Class:** durable; scope boundary+tenant; plain; profile none; module core; serves the keys family.
- **Writer:** [`key@`](/reference/actors/#key).
- **Readers:** [`key@`](/reference/actors/#key); plus the backup job of [`exporter@`](/reference/actors/#exporter), which reads the kind as ciphertext.
- **Exportable:** no; **backed up:** yes.
- **Indexes:** `by_recipient`, `by_purpose`, besides listing by tenant.
- **Data key purposes:** per tenant `data`, `pseudonym`, `pairwise`, `evidence`, `chain`; boundary `grant`, `cookie`, `mac`, `data`. See [the key registry](/reference/keys/#data-keys).

### `KeyRevocation`

Create only (ADR 0041): for every caller, key@ included, store@ refuses an update, a delete and an apply on an existing item. Lease's rule refuses delete and apply only, so it is not the model. Each item revokes one target, the kid of a signing key, a data key generation or a recipient; never a whole purpose. The target, the time and a reason code from a closed list are plain, because signer, entry, exporter@ and ca read them (and watch the kind, so a revocation reaches a published set at once and `ca` stops issuing) to filter published key sets and trust bundles and a sealed kind could not be read there; the operator and any free-text reason are in the audit fact, which is where they belong. key@ writes it only on an operator's declaration signed with a publisher key (ADR 0041, "The declaration"), which the operator command delivers to key@'s admin socket and the signer of any node may relay; a signer never asks on its own. Merged by union on a restore, and re-applied by the roll-forward. A revocation of a boundary's key, purpose or recipient has no tenant (the address carries `-`), only a data key generation of a tenant has one, and key@ writes the kind with no grant, as it writes DataKeyWrap: its authority is the operator's declaration, not a tenant's grant. An apply is refused like an update, whether or not the item exists (the rule table gives key@ create, get and list only).

- **Class:** durable; scope boundary+tenant; plain; profile Operable; module core; serves the keys family.
- **Writer:** [`key@`](/reference/actors/#key), create only (the kind only grows: no update, delete or apply).
- **Readers:** [`key@`](/reference/actors/#key), [`signer`](/reference/actors/#signer), [`entry`](/reference/actors/#entry), [`exporter@`](/reference/actors/#exporter), [`ca`](/reference/actors/#ca); plus the backup job of [`exporter@`](/reference/actors/#exporter), which reads the kind as ciphertext.
- **Exportable:** no; **backed up:** yes.
- **Indexes:** `by_target`, besides listing by tenant.

### `ExportReport`

A destination with no public address cannot read back (ReadBack answers unsupported), so its report says written, carries no purge or read back time, and signer does not count it. signer makes a token key active only after the report of every published key set has the state published, lists the kid and has a read back at most 26 hours old, and the lead time has passed since (REQ-KEYS-085, REQ-KEYS-116); the console shows the state. - **Class:** temp; scope boundary; plain; profile none; module core; serves the data family.

- **Lifetime:** default 48h; maximum 7d.

## Combine rules

| Rule | Meaning |
|---|---|
| `union-forbid-wins` | every layer's policies are compiled into one Cedar set; a forbid anywhere wins, so the built-in baseline holds |
| `shortest-wins` | per field, the shortest duration of any layer |
| `intersection` | the methods every layer allows; a higher layer may only remove or require stronger |
| `override-until-expiry` | an unexpired run-time override wins; otherwise config; otherwise built-in |
| `within-bounds` | the config value, refused at load when outside the built-in bounds |
| `most-specific-wins` | per field, tenant client > tenant > installation client > boundary default (branding is exempt from the direction rule: bounded by config only) |
