The registry lists every [actor](/concepts/families/) of sluis by [family](/decisions/0002-families-of-actors/#the-four-families): the work actors (the adapters among them), store and exporter (data), key (keys), and the audit pieces. Its source is [`docs/architecture/actors.yaml`](https://github.com/truvity/sluis/blob/main/docs/architecture/actors.yaml), and the tables below are generated from it. With the kind registry and the key registry it generates the enforcement layers; each fact has one source.

`just check-actors` (`tools/checks/actors.mjs`) keeps the registry true. It fails when:

- a work actor holds a credential, a holder is not store, exporter, key or an audit piece, a work actor lacks its data, keys or audit-emit port, a port is shared between two families, store lacks one of its four ports, or an actor calls store or key (the ports reach them);
- an egress class or a port is not declared, or a class is declared and unused;
- a record an actor lists is not in `docs/decisions/`, or a requirement record's optional `actors:` names something that is not an actor, or an actor whose requirement areas do not include the record's area;
- the explorer draws a role that is not an actor;
- the label of an actor is not `actor:<name>`, or the tables below are stale (`just actors-write` rewrites them).

It warns, and fails with `--strict-adrs`, when a listed record does not name the actor, a record names an instance (`<actor>@<boundary>`) that is not an actor, or the [language record](/decisions/0012-the-language-follows-the-executable/#per-actor-table) disagrees with the registry on a language or a rule. `just check-registries` checks the actors' key purposes against the key registry and the kinds each actor writes and reads against the kind registry.

Each actor has a GitHub label, `actor:<name>`, on the open issues that build it; the registry's `issues` field lists them. The "Runs" column is the actor's scope: how many instances an installation has of it.

## Open items

None. The workload-issuer key of `sluis-node` is a key of its own in slot `86`, never shared with the token-signing key of `signer` in `9a` ([card slot map](/concepts/keys/#the-card-slot-map)).

### `entry`

Parses each request, validates it against closed parameter lists generated from the contracts, and routes it to the actor that owns the step; it holds nothing.

- **Family:** work; holds no credential at rest.
- **Language:** Rust, rule R2 of the [language record](/decisions/0012-the-language-follows-the-executable/). Gated by spikes S1, S3 and S10; the fallback candidate is Go first.
- **Placement:** one per boundary; any number of instances; on bare-metal, serverless, kubernetes. The only actor reachable from outside: a Unix socket on bare-metal and Kubernetes, loopback TCP on serverless.
- **Ports:** `data`, `keys`, `audit-emit`, `listener`.
- **Calls:** `session`, `exchange`, `console`, `ssh-ca`, `quota`, any adapter.
- **Egress:** none.
- **Key purposes:** `mac` (mac), `pseudonym` (mac).
- **Decisions:** [ADR 0002](/decisions/0002-families-of-actors/), [ADR 0003](/decisions/0003-units-transports-and-fusion/), [ADR 0008](/decisions/0008-boundaries-and-tenants/), [ADR 0011](/decisions/0011-runtimes-and-installations/), [ADR 0012](/decisions/0012-the-language-follows-the-executable/), [ADR 0017](/decisions/0017-identity-and-sign-in/).
- **Requirement areas:** [SEC](/requirements/sec/), [ISO](/requirements/iso/), [QUOTA](/requirements/quota/), [KEYS](/requirements/keys/).
- **Standards:** NC-05 HTTP security headers and cookies: HSTS (RFC 6797), CSP, cookie prefixes; ST-97 ConnectRPC / gRPC / Protobuf.
- **Issues:** [#958](https://github.com/truvity/sluis/issues/958), [#941](https://github.com/truvity/sluis/issues/941), [#796](https://github.com/truvity/sluis/issues/796); label `actor:entry`.
