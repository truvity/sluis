A rule says that an actor may use a verb on a kind. This page lists them all, per actor, together with the call graph. It is generated by `just rules-write` from the [kind registry](/reference/kinds/) (`docs/architecture/kinds.yaml`: the writer and readers of each kind) and the [actor registry](/reference/actors/) (`docs/architecture/actors.yaml`: ports and calls). `just check-rules-page` fails while the page is stale. The store enforces the rules and denies everything else ([the store](/decisions/0005-the-store/#rules)).

The kinds are described on [Kinds](/reference/kinds/); an actor's section on this page is at `/reference/rules/#<actor>`, for example `/reference/rules/#session`.

## The verbs

A rule says that an actor may use a verb on a kind. The store checks it on every call and denies by default ([store rules](/decisions/0005-the-store/#rules)). The two registries generate every layer that enforces it ([registries generate the enforcement](/decisions/0002-families-of-actors/#registries-generate-the-enforcement)).

| Verb | Given to | What it allows |
|---|---|---|
| create, update, delete | the kind's one writer | Changing the kind's items. The store also checks the schema, the version, the bounds and the links on a write. |
| get, list | each reader | Reading items. A sealed value opens only at key@, with a grant sealed for its tenant. |
| watch | each watcher: a reader that the kind names in `watched_by`, exporter@ for an exportable kind, and every reader of a config kind | A change feed from a resume point. A kind that nobody watches, such as an allowance or a rate window, has none. |

A config or secret kind has no actor as its writer: infrastructure as code or the publishing pipeline writes it. The store reads the config bounds of a layered kind itself.
