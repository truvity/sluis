# Upgrade to v1.64

v1.64 is the first release after the one-process release. It adds the documents mode and `sluisctl render`; most of it is
opt-in. This page covers what you must do (the refused presets) and what you should do (leave the deprecated forms).

## Purpose

Move an installation from v1.63 to v1.64, and, if you choose, render its documents with `sluisctl render`
([ADR 0038](../../decisions/0038-estates-render-through-sluis.md)).

## Preconditions

- The installation runs v1.63; to start from older, do [v1.62](v1.62.md) and [v1.63](v1.63.md) first.
- For the documents mode: `sluisctl` of this version on the workstation and in CI, and the installation's facts written as
  an installation document (`apiVersion: sluis.truvity.github.io/installation/v1`, `schemas/config/installation.schema.json`).
- For a Pulumi estate: the v1.64 library, with the release's own `go.mod` require.

## Before you start

- **Presets `server`, `k8s-minimal` and `k8s-openbao` are unavailable.** Each names adapters that are planned and not built;
  loading one fails with a message naming the preset and the missing adapters, unless `adapters` replaces every one of
  them. Looks like: start refuses with that message. See [adapters](../../reference/adapters.md).
- **`aws-eks` is the deprecated name of `k8s-aws`.** It resolves to `k8s-aws` and start logs a warning (it never started
  before: it named the unbuilt trigger `watch`).
- **Values mode is deprecated.** The chart's `config`, `policy`, `exchange.clusters`, `exchange.aws`,
  `githubApps.catalogue` and `slackApps` keep working for one minor and are then removed; `NOTES.txt` says so while one is
  used. `LambdaArgs.Config`, `Policy` and `PolicyPath` also keep working for one minor, and `NewLambda` logs a warning.
- **Rendered documents are trusted.** In documents mode the chart cannot run the loader. It refuses an `http://` OpenBao
  address and a credential-looking key in adapter settings; the service's own loader checks the rest at start, after the
  rollout. Render with `sluisctl render` (never by hand) and run `sluisctl render --check` in CI.
- **A secret an `openbao` or `ssm` Secrets adapter delivers is not projected from a Kubernetes Secret** in documents mode.
- **KMS signing renders no signing Certificate.** With `config.signingKey.kmsWrapped` (or `kms`, or `adapters.signing`) the
  chart renders no signing Certificate and mounts no signing Secret, and refuses `signingKey.additional` and
  `existingSecret`. Drop the chart's default `config.signingKey.file` with `file: null`.
- **`verifyOnly` keys are public only; `until` is required.** A private key stops the start, and the chart refuses private
  material at render. A private key that ever reached a rendered ConfigMap is leaked: rotate it.
- **The audit catalogue needs its schemas.** The audit writer refuses to start without the `.json` schemas; they ship as the
  release asset `sluis-audit-catalogue_<version>.tar.gz` (the configuration schemas as `sluis-config-schemas_<version>.tar.gz`).
- **The release's Pulumi library `require` pin is automatic** (`hack/pin-pulumi-require.sh`, see
  [CONTRIBUTING](../../../CONTRIBUTING.md)): nobody bumps `deploy/pulumi/go.mod` by hand before a tag.
- **Preview before every apply, and read the preview.**
- **Moving the secrets to OpenBao, or signing to KMS, is a migration of its own.** Freeze first (see
  [day two: cutover](../cutover.md) and
  [ADR 0031](../../decisions/0031-a-generic-migration-tool.md)). Deleting keys needs state surgery; the steps are in
  [v1.62 step 6](v1.62.md#6-retire-the-asymmetric-signing-keys-only-when-moving-from-kms-to-wrappedsigning).
- **The `$id` of `sluis.schema.json` says v3** (it said v2). A tool that pins the `$id` must follow.
- **An alerts-only release needs the same `config.signingKey`**, or sets `signingKeyRotationStalled`'s `maxAgeSeconds`.

## Steps

### 1. Replace a refused preset

**Run**: if the document says `preset: server`, `k8s-minimal` or `k8s-openbao`, name `k8s-aws` (or an AWS preset), or list
every adapter under `adapters`. Rename `aws-eks` to `k8s-aws`.

**Expect**: start no longer fails naming missing adapters.

**Verify**: `sluis serve --config <file>` reaches ready; `k8s-aws` with `adapters.secrets: openbao` needs no
`platform.openbao`.

**Rollback**: put the previous document back (on v1.63 the preset loads as before).

### 2. Upgrade the binary, chart and library

**Run**: `helm upgrade` to the v1.64 chart, and on Lambda or EKS bump the Pulumi library; preview, read it, apply.
Nothing else is required: values mode keeps working.

**Expect**: a rolling update with the same objects, plus a deprecation line in `NOTES.txt` if values mode is in use.

**Verify**: `/readyz` is ready; sign-in works; the chart's alerts are quiet.

**Rollback**: `helm rollback`, and the previous library.

### 3. Optional: write the installation document and render

**Run**: write the installation document, then:

```sh
sluisctl render --installation installation.yaml --out rendered/
sluisctl render --installation installation.yaml --out rendered/ --check
```

`--out` writes the service document (`sluis.yaml`, v3) and the policy document (`policy.yaml`, v2),
deterministically, held to the loader the service runs at start. `--check` compares with the files already there and exits
1 on a difference. Commit `rendered/` and run `--check` in CI. Reference:
[sluisctl](../../reference/sluisctl.md#render-an-installation-in-the-two-documents-out),
[the installation document](../../reference/installation-document.md).

**Expect**: `sluis.yaml` and `policy.yaml` in `rendered/`; `--check` exits 0 on a second run.

**Verify**: diff the rendered service document against the one deployed today; the differences should be the ones you
intend. Durations are written without zero units (`1h`, not `1h0m0s`); both read back to the same span.

**Rollback**: none, because nothing deployed changed; delete `rendered/`.

### 4. Optional: pass the documents to the chart

**Run**: set `documents.service` and `documents.policy` to the rendered files and remove `config`, `policy`,
`exchange.clusters`, `exchange.aws`, `githubApps.catalogue` and `slackApps`. The chart puts the documents into their
ConfigMaps unchanged and holds them to what it mounts (release name, `policy.file`, public URLs, audit token, verify-only
keys, the controllers' console URL). It keeps only the deployment-level values. Preview with `helm template`; the
ConfigMaps should equal the files byte for byte.

**Expect**: no change to the running pod if the rendered documents equal the old ones.

**Verify**: `helm template ... | diff` against the committed documents is empty; `/readyz` is ready after the rollout.

**Rollback**: put the values back; `helm upgrade`.

### 5. Optional: Pulumi `LambdaArgs.Installation`

**Run**: replace `LambdaArgs.Config`, `Policy` and `PolicyPath` with `LambdaArgs.Installation`, rendered by the public
`github.com/truvity/sluis/config` package. The library completes it with the instance, region, account and function name
from its arguments when the installation leaves them out, and refuses one that says another. Preview, read it, apply.

**Expect**: the layer version changes only if the rendered documents differ.

**Verify**: no `NewLambda` deprecation warning; a test invoke returns `"outcome":"ran"`.

**Rollback**: put `Config` and `Policy` back; they keep working for one minor.

### 6. Optional: the OpenBao Secrets adapter

**Run**: set `adapters.secrets: {adapter: openbao}` with `address` (https only), `caFile`, `mount`, `namespace`, `root` and
`auth{method, mount, role, tokenFile}`, and give the login its OpenBao policy
([configuration](../../reference/openbao-secrets-adapter.md)). Layout:
`<root>/private/config/<name>`, `<root>/private/credentials/<kind>/<id>/<ref>`, `<root>/export/<path>`; the root is
`sluis` in the installation's own OpenBao namespace (recommended) or `sluis/<instance>`. `private` and `export` are
reserved. On Kubernetes it composes with `config.secrets.source: file`; the chart checks `caFile` and `auth.tokenFile`
against `exports.openbao.caBundle` and `exports.openbao.token.audience`.

If the credentials already live elsewhere, move them with `sluis migrate` ([migrate state](../migrate-state.md)) in a
frozen window.

**Expect**: the first start writes under the root; a `cas_required` mount is refused naming it.

**Verify**: the exports pass writes `<root>/export/*`; consumers' External Secrets read it.

**Rollback**: point `adapters.secrets` back at the previous adapter; the old store was not changed by the copy.

### 7. Optional: `signingKey.verifyOnly` for a cutover to `kmsWrapped`

**Run**: list the old file keys' public halves under `signingKey.verifyOnly[]` (`kid` optional, `alg` optional, `until`
required) so tokens they issued keep verifying across the cutover. The chart mounts them from a ConfigMap
(`signingKey.verifyOnly[].pem`).

**Expect**: the JWKS publishes the old `kid`s and the new ones.

**Verify**: fetch the JWKS (the discovery document's `jwks_uri`) before and after; the old `kid`s are in both.

**Rollback**: remove the entries; tokens the old keys signed then fail to verify.

## Afterwards

- Watch `signingKeyRotationStalled`: unset, `maxAgeSeconds` is `rotateEvery` plus two hours with kms-wrapped signing.
- Remove values mode and `LambdaArgs.Config` before the next minor: both are removed then.
- Tell the estate repositories that `sluisctl render --check` belongs in their CI.
