# Upgrade audit to v1.74

Unreleased. v1.74.0 changes the shape of a catalogue: an action declares a `category`, and `profiles` on an action is
deprecated. A reader that predates it rejects a catalogue written in the new shape, and the index stops. This page is the
order that avoids that, and how to tell when it happened.

## Purpose

Move an audit installation that runs the writer, `audit-observe` and `audit-query` (and anything else that reads the
archive) to v1.74 without the index stalling behind a catalogue its reader does not accept.

## Preconditions

- You run an earlier audit release for every component, and you know which of them are readers: `audit-observe`, `audit-query`
  and the `audit` command line when it reads the archive.
- For Kubernetes, the `audit` chart's release for each; for AWS, the Pulumi library and zips of the same release.

## Before you start

- **Readers must run the same audit release as the writer, or a newer one.** The writer registers each catalogue version it
  is given into the archive, and every reader loads those catalogues and validates them against the schema of its own
  release. A reader that is older than the writer therefore meets catalogues it cannot read. Upgrade the readers first and
  the writer last, and never leave a writer ahead of a reader.
- **v1.74.0 changes the catalogue shape.** The roster catalogue 1.11.0 declares `category: ...` on an action and no
  `profiles: [...]`, which the `catalogue.schema.json` of earlier releases requires. An older reader refuses the first
  record of a 1.11.0 catalogue with "does not satisfy catalogue.schema.json ... missing property".
- **The symptom is silent without the alerts.** The pod stays running; the indexer retries every pass, the index stops at its
  cursor and the console's audit page goes empty. From this release `/readyz` of `audit-observe` fails after
  three failed passes, and the chart's `AuditIndexStalled` and `AuditIndexPassesFailing` alerts fire
  ([respond to alerts](../respond-to-alerts.md#auditindexstalled)). Enable the rules before the upgrade.
- **The default poll of `audit-observe` is now 5 minutes** (it was 30 seconds). Without a `wake` the worst-case delay from
  a record being acknowledged to being searchable is `settle` plus `interval`, seven minutes with the defaults. Configure
  `wake.sqs` or `wake.nats`, or set `interval` back, if that is too slow
  ([configuration](../../reference/configuration-observe-query.md#indexer)).

## Steps

1. **Upgrade `audit-observe` and `audit-query`** to v1.74 (the chart release, or the Pulumi library and zips of the same
   release). Verify: both pods are Ready; `/readyz` answers 200; `audit_observe_pass_since_success_seconds` stays below the
   interval. Roll back: the previous release; nothing in the index changed.
2. **Upgrade the writer, the receiver and the notary.** Verify: the writer's start-up record carries the new version; a record
   of the new catalogue is indexed (the search shows it within `settle` plus `interval`). Roll back: the previous writer; a
   catalogue it registered stays in the archive, which readers of v1.74 read.
3. **Publish the new catalogue version last**, once every reader is on v1.74. Verify: no `an indexing pass failed` line in
   the indexer's log.

## Afterwards

- If a reader was upgraded late, the indexer resumes from its cursor on its own once it runs v1.74 and indexes what it missed;
  nothing is indexed twice.
- The detailed entries are in the [CHANGELOG](../../../../CHANGELOG.md).
