{{- else -}}

Every component is configured by one file, its `config:` block, rendered as it
stands and validated against the schema its binary validates it against. A
secret is never in it: the file names an environment variable, and `secretEnv`
puts a Secret's key there. Telemetry is the OTEL_* environment, set by the
platform. docs/audit/reference/configuration.md lists every key.

{{ if not .Values.writer.enabled -}}
{{- else if eq .Values.mode "stream" -}}
Stream mode: {{ .Values.replicas }} receiver(s) publish to the stream, and
{{ .Values.writer.consumers }} writer(s) consume it. The receivers hold neither
the bucket nor a key.
{{- else -}}
Direct mode: the front door is the write path. Every batch is put before it is
acknowledged, and how many objects a day becomes is decided by the emitter's own
batch size and flush interval. `mode: stream` puts a receiver in front and the
writers behind a durable consumer, which is what makes a writer that is down a
backlog rather than a hole.
{{- end }}

Check what a profile keeps, with the audit CLI (the images have no shell and
the writer's has no CLI in it):
  kubectl get configmap {{ include "audit.fullname" . }}-deployment -o jsonpath='{.data.deployment\.yaml}' > deployment.yaml
  audit profile explain <name> --deployment deployment.yaml

Verify the chain yourself, with nothing but the archive and the public key:
  audit verify --profile <name> --from <date> --to <date> --bucket <bucket> --public-key <file>
